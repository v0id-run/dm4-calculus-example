### План реализации и тестирования

**Итерация 1.**
  
Параллельно разрабатываются клиентская и серверная части сервиса авторизации и личного кабинета, а также серверная часть сервиса обработки домашних заданий.  
В рамках разработки серверной части авторизации полностью (со всеми атрибутами и методами) реализуются следующие классы (здесь и далее расположены в порядке реализации):  
 
* User 
* Administrator
* Student
* Teacher
* AuthorizationService

Разработанные методы классов покрываются модульными тестами. На стороне клиента реализуются все элементы указанные в требованиях.
Параллельно создаются клиентская часть (для студента, преподавателя, администратора) и серверная часть личного кабинета. На серверной части создаётся класс Account с методами "Смена пароля", "Выдача информации" (вид информации зависит от роли пользователя), "Исполнение sql-запросов". На клиентской части создается веб-интерфейс для отображения информации и поля для смены пароля. Для личного кабинета администратора создается поле для ввода sql-запросов.
 
В рамках разработки серверной части сервиса обработки домашних заданий полностью реализуются классы:  

* Asignee
* Comment
* Task
* TaskEstimation
* Homework 
* HomeworkEstimation

После реализации очередного класса его методы покрываются модульными тестами.

**Итерация 2.**

Параллельно разрабатывается клиентская часть сервиса обработки домашних заданий и сервис поддержки вывода формул.     
В рамках разработки клиентской части сервиса обработки домашних заданий реализуются все элементы описанные в требованиях.
Клиентская и серверная части сервиса поддержки вывода формул разрабатываются параллельно. В рамках разработки серверной части полностью реализуются следующие классы:  

* Formula
* InferenceRule
* Substitution
* ModusPonens
* Theorem
* Calculus
* Context
* HistoryPair
* StateHolder

После реализации очередного класса его методы покрываются модульными тестами. На стороне клиента реализуются все элементы указанные в требованиях.

**Итерация 3.**

Параллельно разрабатываются клиентская и серверная части сервиса проверки истинности формул. В рамках разработки серверной части сначала полностью создаются классы,описывающие грамматику для разбора пропозициональных формул:  

* Scope
* Operator
* NegationTerm
* ConjunctionTerm
* OpConjunctionTerm
* DisjunctionTerm
* OpDisjunctionTerm
* ImplicationTerm
* OpImplicationTerm
* IdentityTerm
* OpIdentityTerm
* Proposition

Затем параллельно полностью реализуются классы Parser и PropositionalLogicChecker. Все методы разработанных классов покрываются модульными тестами. 
После создания тестов параллельно для каждого исчисления в требованиях разрабатываются классы, описывающие грамматику их разбора, а также классы XXXChecker(F1Checker - валидатор для функционального исчисления первого порядка, F2Checker - для функционального исчисления второго порядка, ModalLogicChecker - для модальной логики, SequenceChecker - для секвенций). Затем пишутся дополнительные модульные тесты для Parser с использованием новых грамматик.  
На стороне клиента реализуются все элементы указанные в требованиях.
