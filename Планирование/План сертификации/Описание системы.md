## Общее описание системы

***Описание архитектуры***

ПО имеет клиент-серверную архитектуру. У клиентов присутствует только презентационная логика. Логика работы отдельных сервисов и логика доступа к ресурсам остаются на сервере. Сервер является отдельным физически отдалённым от клиента сервером. 

Система представляет собой набор следующих компонентов:
 
* личный кабинет;
* сервис обработки домашних заданий;
* сервис проверки истинности формулы;
* сервис проверки истинности формул;
* авторизация.

Каждый  из сервисов предоставляет собственную функциональность.

***Функциональность личного кабинета***

*Личный кабинет* *для преподавателей* предоставляет информацию об успеваемости учебных групп, планы.

*Личный кабинет* *для студентов* предоставляет информацию о домашних заданиях и контрольных работах, статусе и дате их выполнения, успеваемости студента.

*Личный кабинет* *для администраторов сайта* предоставляет возможность:

1. делать запросы к БД;
2. просматривать логи системы.

***Функциональность сервиса обработки домашних заданий***

*Сервис для преподавателей* предоставляет возможность:

1. создаввать домашние задания;
1. выдавать домашние задания;
1. проверять домашние задания.

*Сервис для студентов* предоставляет возможность:

1. просмотра всех выданных домашние задания;
1. отправки заданий на проверку.

***Функциональность сервиса поддержки вывода формул***

*Сервис предоставляет возможность*:

1. задания *контекста* ввода;
1. проверка возможности вывода формулы по modus ponens в зависимости от текущего контекста;
1. осуществление *замены переменных* в известной в контексте формуле;
1. проверка корректности и исполнение записанного *modus ponens*;
1. отображение *теоремы*, имеющейся в контексте, по её краткому обозначению.

***Функциональность сервиса проверки истинности формул***

*Сервис предоставляет возможность:*

1. рендерить введенную пользователем на языке Logical Formulas  формулу в Latex;
2. проверять введенную пользователем формулу при помощи главной интерпретации исчисления:
    * для $P_1$, $P_2$​ - обычная матлогика;
    * для $F_1$, $F_2$ - метод резолюций;
    * для $P_I$​ - трёхзначная псеводобулева алгебра;
    * для модального исчисления - некоторая модель Крипке;
3. выводить на экран результат в виде текстовой строки со значениями "Истинна" и "Не истинна".

***Функциональность авторизации***

*Сервис предоставляет возможность*:

1. аутентификации пользователей при помощи логина и пароля;
1. изменения пароля путем введения старого и нового паролей.

***Методы обеспечения безопасности***

*Для обеспечения безопасности* в системе используется механизм идентификации и  аутенфикации.

Идентификатором в данном случае будет являться уникальное сочетание логина и многоразового пароля.

Аутенфикация происходит следующими образом: при вводе субъектом своего пароля подсистема аутентификации сравнивает его с паролем, хранящимся в базе эталонных данных в зашифрованном виде при помощи алгоритма хешировавания sha256, то есть каждый пароль будет представлен в таком виде - *sha256(sha256(passwd) + "dm4dm4dm4dm4")*; в случае совпадения паролей подсистема аутентификации разрешает доступ к ресурсам системы.

*Разделяемые ресурсы* в системе:

* план домашних заданий;
* план контрольных работ.

То есть пользователь не будет иметь доступ к чужим личным данным, а также решениям и оценкам.

*Отказоустойчивость* системы реализована на основе независимости каждого из компонентов друг от друга: при падении одного из сервисов, перестает работать только часть функциональности, а остальные части системы продолжают.
