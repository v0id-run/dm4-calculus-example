# Определения и термины

1. **Commit** представляет собой очередную версию проекта. Он содержит информацию об изменениях относительно прошлой версии в индексированных файлах, а также дату создания, уникальный идентификатор commit\`а и идентификатор автора.
1. Множество commit\`ов представлено древовидной структурой, состоящей из веток (**branch**). Ветвление происходит, если несколько commit\`ов имеют одного общего предшественника (являются разными развитиями одной и той же версии). Основной веткой является ветка **master**. Ветки можно сливать (**merge**) в одну. При этом в результирующем commit\`е будут представленны все дополнения из последних версий сливаемых веток. Таким образом, ветвление удобно использовать для расширения функционала программного продукта (новый функционал разрабатывается в отдельной ветке и по готовности вливается в основную).
1. **Git**  - распределённая система контроля версий.
1. **Gitlab** - веб-сервис для хостинга и совместной разработки проектов, использующий Git в качестве системы контроля версий.
1. **Merge conflict** - проблема, возникающая при слиянии веток, связанная с наличием в сливаемых ветках разных изменений в одних и тех же файлах.
1. **Merge request** - позволяет перед коммитом в master ветку отправить внесенные изменения другим разработчикам проекта, это аналог.Merge request позволяет предотвратить внесение некорректных изменений, которые сломают проект.
1. **Индексированные файлы** - это файлы, отслеживаемые git, текущие версии которых были добавлены в список изменений для следующего commit\`а при помощи команды add.
1. **Непрерывная интеграция** (CI, англ. Continuous Integration) — практика разработки программного обеспечения, которая заключается в постоянном слиянии рабочих копий в общую основную ветвь разработки и выполнении частых автоматизированных сборок проекта для скорейшего выявления потенциальных дефектов и решения интеграционных проблем.
