## Трассировочная база данных

Представляет собой файл `db.csv`, лежащий в папке */trace*. Содержит информацию о связях различных единиц конфигурации между собой. Каждая строка этой базы хранит:

* Идентификатор родительской единицы конфигурации
* Тип родительской единицы конфигурации
* Версию родительской единицы конфигурации
* Отношение между родительской и дочерней единицами конфигурации
* Идентификатор дочерней единицы конфигурации
* Тип дочерней единицы конфигурации
* Версию дочерней единицы конфигурации

Список обозначений типов:

* *SYSREQ* - требования к системе, расположение: */Спецификация требований/Общее описание*;
* *SOFTREQ* - требования к ПО, расположение: */Спецификация требований/Конкретные требования* и */Спецификация требований/Конкретные требования/Компоненты системы*;
* *ART* - артефакт проектирования, расположение: *todo*.

Крайне рекомендуется ввести псевдоним для команды:
```bash
alias='python <path_to_trace_directory>/trace.py'
```

### Требования

- Python 3.6+
- `pip install tabulate`
- `pip install gitpython`

### Как использовать

* `trace ls [<option>] <relative_path>`
    Выводит список единиц конфигурации, записанных в файле, расположенному по **относительному** пути.  
    Опции `<option>`:
    - `-t` выводит только те единицы конфигурации, которые находятся в трассировочной базе.
    - `-n` выводит только те единицы конфигурации, которые не находятся в трассировочной базе.

* `trace add <from_unit> <from_type> <from_version> [<relation> <to_unit> <to_type> <to_version>]`
    Добавляет в трассировочную базу новую запись, причём осуществляется проверка существования подобной записи в базе. Если указаны только обязательные аргументы команды, то единица конфигурации добавляется в базу, но для неё не устанавливается каких-либо отношений с другими единицами конфигурации; данная ситуация нормальна при добавлении производных единиц конфигурации или требований к системе.

* `trace update <unit>`
    Устанавливает актуальную версию для данной единицы конфигурации во всех записях трассировочной базы.

* `trace rel [<options>] <unit>`
    Выводит все записи из трассировочной базы данных, где участвует указанная единица конфигурации `<unit>`.  
    Опции `<options>`:
    - `-p` выводит только те записи, в которых `<unit>` является родительской единицей конфигурации (расположен слева).
    - `-c` выводит только те записи, в которых `<unit>` является дочерней единицей конфигурации (расположен справа).

* `trace der <relative_path>`
    Выводит производные единицы конфигурации - такие, для которых не существует записи с отношением *generates* и `<unit>` в правой части записи - в файле, расположенному по **относительному** пути `<relative_path>`. Вместо `<path>` можно передать опцию `--all`, в этом случае поиск будет производиться во всем файлам репозитория.

* `trace smell [<option>|<relative_path>]`
    Проверяет актуальность данных в трассировочной базе. Извлекает из *git log* информацию о версиях единиц конфигурации в репозитории и сравнивает её с той, что содержится в трассировочной базе. Вместе с этим проверяет корректность простановки типов единиц конфигурации. В случае нахождения неверных данных, выводит таблицу с информацией о несоответствии: номер строки в базе, единица конфигурации, тип несоответствия, актуальная версия (из git) и имеющаяся (из trace).  
    Опции:
    - `--all` проверяет все файлы документации.
    - `<relative_path>` проверяет несоответствия только в указанном файле.
